Example workflow reviewed

Workflow: browser-driven Upwork sourcing loop using Codex, Chrome CDP, local proposal inventory, and a preflight script that decides whether Connects may be spent.

Goal: let the agent inspect jobs and prepare evidence while preventing unsafe proposal submission, duplicate browser tabs, stale inventory use, or unverified payout claims.

Side-effect map

Action Risk Required evidence gate
Open Upwork job detail in Chrome Low risk, but duplicate tabs degrade session state and user trust. Use existing Upwork tab when present. Only open a tab with an explicit --open-if-missing path. Log tab count and duplicate URL groups.
Click Apply or Submit Proposal Connects spend, external message, irreversible proposal history. Fresh preflight must return ALLOW, required Connects must be known, job must match the approved wedge, and the exact proposal text must be staged.
Record Upwork payout as withdrawn False revenue claim if available balance is confused with completed withdrawal. Require completed withdrawal screenshot or payment confirmation artifact. Available balance evidence is readiness only.
Send client or community reply External reputation impact and possible policy breach. Require approved exact text, target identity, destination URL/thread, and post-send screenshot or message ID.

Example findings

  1. Preflight denial must be terminal. If lead inventory has zero safe-to-submit candidates, the agent may inspect pages read-only but must not spend Connects or submit a proposal.
  2. Browser control must preserve state. A profile mismatch can make the Chrome extension appear broken even while another profile is healthy. The workflow should keep using CDP/read-only automation and avoid profile file mutation.
  3. Money claims need completed-payment evidence. A funded milestone, available balance, and completed withdrawal are three different states. Reports must label them separately.

Patch plan excerpt

Priority Patch Acceptance test
P0 Add a no-Connect controller that blocks spend, posting, payout recording, and catalog publishing unless each gate has evidence. Controller returns allowed_count=0 and submitted_or_spent_connects=false when inventory is stale or unsafe.
P0 Add a duplicate-tab audit before any Upwork browser action. Audit reports category counts and duplicate URL group count without opening or closing tabs.
P1 Add an execution packet template for payout actions that distinguishes readiness from completion. Completion gate rejects missing or available-balance-only evidence.
