Example workflow reviewed: a browser-driven Upwork sourcing loop using Codex, Chrome CDP, proposal inventory, and a preflight script that decides whether Connects may be spent.

Side-effect map excerpt

Action Risk Required evidence gate Status
Open Upwork job detail Duplicate tabs degrade session state. Use existing tab; only open with an explicit open-if-missing path; log duplicate URL groups. Gate required
Click Apply or Submit Proposal Connects spend plus irreversible external proposal. Fresh preflight must allow spend, required Connects must be known, and exact proposal text must be staged. Hard stop
Record payout as withdrawn False revenue claim if available balance is treated as completed withdrawal. Require completed withdrawal screenshot or payment confirmation artifact. Hard stop

Example findings

  1. Preflight denial must be terminal. If lead inventory has zero safe-to-submit candidates, the agent may inspect read-only pages but must not spend Connects or submit a proposal.
  2. Browser control must preserve state. A Chrome profile mismatch can make an extension appear broken while another profile is healthy. Continue with CDP/read-only automation rather than mutating browser profile files.
  3. Money claims need completed-payment evidence. Funded milestone, available balance, released funds, and completed withdrawal are separate states.

Patch plan excerpt

  • Add a no-Connect controller that blocks spend, posting, payout recording, and catalog publishing unless each gate has evidence.
  • Add a duplicate-tab audit before every logged-in Upwork browser action.
  • Add an execution packet template for payout actions that distinguishes readiness from completion.

Boundary: diagnostic only. No platform bypassing, credential storage, autonomous posting without approval, or revenue guarantee.
